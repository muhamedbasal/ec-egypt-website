# خطة EC Egypt لرفع كفاءة الموقع خلال 90 يومًا

تاريخ إعداد الخطة: 2 أكتوبر 2026. المستودع المحلي: `D:\GitHub\01_active\ec-egypt-website`.

## خلاصة الفحص

- المستودع يحوي 4 صفحات أساسية مع عناوين ووصف وcanonical وبيانات منظمة و`robots.txt` و`sitemap.xml`. توجد صور ذات أبعاد معلومة وتحميل كسول وصورة رئيسية ذات أولوية تحميل عالية؛ لا يوجد قياس ميداني يثبت أن الأداء سيئ.
- كانت نماذج القياس تحتوي معرّفات GA/GTM تجريبية لا تجمع تقارير EC موثوقة. لا توجد لدينا صلاحية أو ملفات تصدير تخص GA4 أو Search Console أو Analyzeez لهذا الموقع. لذلك الزيارات والعملاء المحتملون وترتيب الكلمات **مجهولة**، وليست صفرًا.
- فحص HTTP للنسخة المنشورة بتاريخ 2 أكتوبر أعاد 200 للصفحات الإنجليزية، لكنه ما زال يكشف مؤشرات placeholders واختلاف hreflang؛ والروابط الأربعة `/ar/` و`/ar/about.html` و`/ar/products.html` و`/ar/contact.html` رجعت 404. لذلك تغييرات المستودع العربية لا تظهر على الموقع العام حتى الآن.
- لم يكن النموذج يرسل إلى backend صالح. كانت واجهة المستخدم تعد برسالة نجاح رغم أن المسار يجهز رسالة واتساب فقط. التعديل يوضح أن العميل يراجع الرسالة ويرسلها بنفسه. فتح واتساب أو تسجيل نقرة لا يثبت استلام طلب.
- العربية كانت تبدل داخل الرابط نفسه. أصبح لها HTML ثابت على `/ar/` وصفحات فرعية مولدة من نصوص الترجمة الموجودة، مع canonical و`hreflang` وروابط لغة متبادلة وإضافات لخريطة الموقع.
- كتالوج الجذر يعرض أصنافًا لا تتفق مع البطاقات والبيانات المنظمة. أزيلت روابط الأصناف غير الموجودة ووُجهت روابط الكتالوج إلى أصناف موجودة. لا تُنشأ بيانات مواصفات أو أسعار أو توافر من دون مراجعة تجارية.
- التموضع التجاري المقترح هو توريد البقول والحبوب لتجار الجملة ومصانع الأغذية في مصر، مع إبقاء أي نشاط تصدير حقيقي. هذا اقتراح يحتاج أن يطابق المبيعات الفعلية قبل أن يصبح ادعاءً ثابتًا.

## الخطة بحسب المرحلة

### الأيام 1–30: إيقاف الالتباس وبناء خط أساس

1. **الفريق التجاري:** اعتماد من يستقبل استفسارات واتساب والبريد، وزمن الرد المستهدف، وتعريف مكتوب للاستفسار المؤهل. راجعوا الهاتف، البريد، المنتجات، المناشئ، درجات الجودة، الحد الأدنى، العبوات، وجهات التسليم والادعاءات المؤسسية قبل اعتمادها.
2. **المسؤول التقني/القياس:** ربط GSC وGA4 المملوكين لـEC أو توفير تصدير يومي/أسبوعي بملفات CSV محلية. تأكدوا أن العقار والنطاق يعودان لـ`ec-egypt.com`. لا تستخدموا معرّف Admiral. أكملوا مراجعة الموافقة والخصوصية قبل إرسال أي بيانات إلى مزود تحليلات.
3. **استقبال الطلبات:** إن أريد حفظ الطلب قبل فتح WhatsApp، فاختاروا backend يملكه EC مع إشعار ومسؤول متابعة. المسار الحالي يوضح أن الزائر سيراجع ويرسل الرسالة يدويًا؛ لا يعرض نجاح حفظ غير حقيقي. لا تطلبوا من الزائر بيانات زائدة.
4. **أساس SEO/AEO/GEO:** راجعوا النسخ الإنجليزية والعربية وخريطة الموقع والفهرسة. أضيفوا صفحات منتج مستقلة فقط عندما تتوفر حقائق شراء مميزة معتمدة. أسئلة الأسئلة القصيرة والجداول مفيدة للمشتري والإجابات الآلية حين تجيب بدقة؛ لا يوجد ضمان ترتيب أو اقتباس.

**معيار هذه المرحلة:** خط أساس صالح من أول 28 يومًا بعد ربط القياس؛ تتبع مستقل بين نقرة واتساب، استفسار وصل فعلًا، استفسار مؤهل، عرض سعر وطلب مؤكد. كل استفسار مستلم له مالك وحالة متابعة.

### الأيام 31–60: تحسين صفحات القرار التجاري

1. بعد اعتماد الحقائق، ابدأوا بخمس صفحات/مجموعات: الفول، الحمص، العدس، الترمس، والأرز. اشرحوا المنشأ/الدرجة/المقاس/التعبئة/الاستخدام/الحد الأدنى/مهلة التوريد حسب المتاح فعلًا.
2. أضيفوا مسار طلب عرض سعر واضحًا على كل صفحة، مع حفظ المصدر واللغة والمنتج بعد موافقة العميل. لا ترسلوا الاسم أو البريد أو الهاتف إلى GA4.
3. راجعوا تناسق `Organization` و`Product` و`Breadcrumb` و`FAQ` مع النص الظاهر. لا تضيفوا سعرًا أو مراجعات أو عرضًا منظمًا افتراضيًا.
4. حسّنوا الوصلات الداخلية من صفحة المنتجات والصفحات الرئيسية، ثم راجعوا تقارير Search Console لتحديد الفئات ذات الطلب الحقيقي بدل اختيار الكلمات بالتخمين.

**معيار هذه المرحلة:** كل صفحة مختارة تتضمن معلومات توريد معتمدة وCTA واضحًا، ويمكن ربط الاستفسارات المستلمة بالصفحة والمنتج واللغة دون جمع بيانات شخصية في التحليلات.

### الأيام 61–90: زيادة التحويل وتحسين ما أثبتته البيانات

1. أعدوا أدلة شراء قصيرة تجيب عن الفروق بين المنتجات ومقاساتها وشروط توريدها، باستخدام معلومات موثقة ومراجع واضحة عند اللزوم.
2. انشروا حالة توريد فقط بموافقة العميل وبيانات صحيحة. اربطوا الصفحة بالمنتجات والطلب المناسب.
3. راجعوا أسبوعيًا الاستعلامات التجارية غير المرتبطة بالعلامة، النقرات، الاستفسارات المؤهلة، عروض الأسعار، الطلبات المؤكدة، زمن الرد ونسبة المتابعة.
4. نفذوا تجربة واحدة صغيرة في كل مرة (عنوان/CTA/نموذج/ترتيب المعلومات)، وسجلوا تاريخها قبل مقارنة الفترات. لا تفسروا تغير الترتيب وحده على أنه زيادة مبيعات.

**معيار هذه المرحلة:** مقارنة 28 يومًا بخط الأساس على الزيارات المؤهلة والطلبات الفعلية والعروض والإغلاق. هدف مضاعفة الزيارات ليس نتيجة مضمونة، ولا يمكن تعيين هدف رقمي مبرر قبل استقرار القياس.

## التشغيل والقياس

من جذر المستودع:

```powershell
python tools/growth_ops.py --offline
python tools/growth_ops.py --live
```

`--offline` يفحص ملفات المصدر والصفحات الثابتة والأصول وروابط sitemap وschema. `--live` يضيف طلبات HTTP قراءة فقط إلى صفحات EC العامة وملفات robots/sitemap وllms وصفحة اختبار 404. لا يرسل نماذج أو رسائل. تقارير JSON وMarkdown تحفظ افتراضيًا خارج المستودع في `%USERPROFILE%\EC-Egypt-Analytics\growth-ops`.

### إدخال بيانات Analytics اختياري

الأداة لا تتصل بـAnalyzeez ولا تضغط زر تحليل، ولا توجد لها مفاتيح EC. عند إنشاء تصدير يومي محلي من حساب EC، عيّن `--imports` إلى manifest JSON خارج Git. ابدأ بنسخ القالب أدناه إلى مجلد التقارير الخاص واملأ مسارات CSV؛ لا تحفظ ملفات العملاء أو credentials في المستودع.

```json
{
  "site": "https://ec-egypt.com",
  "gsc": {"property": "sc-domain:ec-egypt.com", "file": "gsc-daily.csv"},
  "ga4": {"hostname": "ec-egypt.com", "property_id": "REPLACE_WITH_EC_PROPERTY_ID", "file": "ga4-daily.csv"}
}
```

ملف GSC يحتاج أعمدة `date,clicks,impressions`. ملف GA4 يحتاج `date,sessions,organic_sessions`. يجب أن يغطي المصدر آخر 56 يومًا حتى تقارن الأداة 28 يومًا بآخر 28. لا تضع أسماء أو هواتف أو عناوين أو استفسارات عملاء في ملفات هذه المؤشرات.

```powershell
python tools/growth_ops.py --imports "$env:USERPROFILE\EC-Egypt-Analytics\ec-imports.json" --force
```

أي بيانات ناقصة تظل `unavailable`/`partial` وليست صفرًا. وجود CSV لا يثبت وحده صحة ملكية العقار أو أن التصدير حديث؛ يراجع المالك مصدره وتاريخه.

## ما يحتاج قرارًا/وصولًا من صاحب الموقع

- بيانات GA4 وGSC أو تصديرات EC؛ Analyzeez لا يملك اتصالًا معروفًا بهذا الموقع في بيئة الفحص.
- اختيار backend يملكه الموقع إذا كان المطلوب حفظ RFQ قبل واتساب وإشعار فريق المبيعات.
- تأكيد المواصفات والمنتجات والمناشئ والأرقام المؤسسية والقدرات التجارية قبل نشر صفحات أكثر تفصيلًا.
- فحص الموقع المنشور ومقاييس الأداء الحقيقية وإتمام أي نشر؛ تغييرات هذا العمل محلية ولم تُنشر.
- قبل النشر، افحص إعدادات الاستضافة لتعرف إن كانت الجذر المنشور متصلًا بهذا المستودع، وأصلح 404 للصفحات العربية والتحذيرات المرصودة. لا يكفي تحديث sitemap قبل أن تصبح الملفات متاحة من الخادم.
